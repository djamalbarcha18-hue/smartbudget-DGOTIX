## Overview

The lib/features directory groups feature-specific code for the application. At the root level this directory primarily organizes submodules rather than exposing many root-level implementation files; several feature implementations are contained entirely in their own subdirectories. The documented subdirectories each focus on a single feature and split responsibilities into layered code (for example domain, application, data, and presentation layers) or platform-specific helpers where applicable.

Specifically, the backup subdirectory holds the backup feature implementation and is split into platform I/O helpers and feature sublayers (application, domain, presentation) to manage export/import of application data. The referrals subdirectory contains the referrals feature implementation separated into domain, application, data, and presentation layers and centers on referral rewards and their effects on product features. The statement_import subdirectory provides feature-level code and submodules to import, parse, and represent tabular statement data, with the core logic located in its domain subdirectory. Together, these subdirectories show a consistent organization where each feature encapsulates its own domain logic and supporting layers, allowing the larger system to include or modify features without changing unrelated code.


### File Organization

This directory groups code by feature: each feature lives in its own subdirectory and is further split into layered submodules (where documented). Root-level files are minimal or absent; features provide their own domain/application/data/presentation divisions or platform helpers as described in their subdirectories.
